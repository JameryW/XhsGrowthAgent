# 09-20-release-has-no-decider — `release` 的答案该不该有粒度

> 入口：`docs/execution-plane.md` §7.1 的登记清单第 1 条（也是第 3 条 —— 见 §1 P10）
> ——「`release` 的 4 个 `False` 出口（空 id · 不是我们的 · `except` · `released` 假），
> 与前两条同形，后果轻 —— `end_lease` 不据此做决定。**未量。**」

## 0. 这一片要回答什么

`renew` 的两种非答案在 #638 分开了，因为**心跳据此做决定**（停 / 不停）。`acquire` 的两种拒绝
在 #636 分开了，因为**接管扫描据此做决定**（拒绝 / 照跑）。`release` 的出口至今仍塌成一个
`False`，登记里给的理由是「后果轻」—— 那是一个**估的**理由。

所以本片要回答的是：**一个没有人据以做决定的答案，值不值得有粒度？**

「后果轻」不是理由，「**没有决定者**」才是 —— 而后者可以量：数一数有多少处**读**它的值。
这个量顺带把一条更一般的原则钉下来（§3 裁定 A），并解释 `acquire` / `renew` 为什么被分开
而 `release` 不该。

附带两件本片在侦察期就撞上的事（都不是新的设计判断，是**承袭来的文字**）：

- §7.1 那张清单里，第 1 条与第 3 条是**同一条登记的两份副本**，而标题写着「三条」。
  来源可查：`87e55a09` 把原第 3 条提到第 1 位时**没删原件**（§1 P10）。
- 陈述那条不变量的句子（`:51`）把它归给「§0 第一条性质」—— **§0 里没有这条性质**，
  它是 §2 不保证 1（§1 P11）。同一句还在说那个形状「要消灭」，而 `release` 今天仍是它。

### 2.1 「4 个出口」的两种口径

| 口径 | 数 | 出处 |
| --- | --- | --- |
| 字面 `return False` 的语句数 | **3** | `:534` `:539` `:549` |
| **能答出 `False` 的出口数** | **4** | 上面三个 + `:550`（`released` 为假） |

登记写的是 4 —— 与「能答 `False`」的口径一致。**两种数都要写在文档里**，否则下一个人按
字面量数一遍得到 3，会以为登记过期了（这正是本仓最常发生的那种「承袭文字」）。

### 2.2 谁读这个答案（本片的核心量）

探针：`_probe_release_readers.py`。它对每个租约函数数两类调用点（模块内 / 模块外），并按
**AST 父节点**判定值是否被读（裸 `await x()` 是丢弃；赋值 / return / 传参 / 比较是读）。

```
release          sites=0 reading=0  [NO READER]      (× 模块外)
release          discards :729 in end_lease()        (× 模块内)
acquire          reads    _takeover.py:139
start_lease      reads    _runner.py:458
end_lease        discards _runner.py:481
renew            (无任何调用点)
```

★ **这个探针自己错了三次，三次都是「回答了另一个问题」**（与 #636/#638 那些判据错误同族）：

1. **`grep "await release("`** —— 只匹配**裸名字**，而本仓用的是 `await leases.release(`，
   于是整个第二次扫描报告「0 读者」；真相是这个 grep 什么也没看见。
2. **只按属性名匹配** —— 把 `backend/services/cdp_session_lock.py:310` 的 `lock.release()`
   （`asyncio.Lock`）与 `pg_hold.release()`（PG advisory lock）都算成了租约的 `release`。
   修法：**接收者必须绑定到租约模块**（从 import 解析），不是看属性叫不叫 `release`。
3. **判「值被读」时没先穿过 `Await`** —— 于是每一条裸 `await x()` 都被报成「读值」，
   `end_lease:729` 这个**恰好是本片要证明的丢弃点**反而看不见。

⇒ 三条共同形状：**探针说的不是它被问的那件事，而输出看起来都很正常。**

### 2.3 一次失败的 release 代价（有界，且退化成设计中的路径）

失败后行留在 `held`、`heartbeat_at` 是最后一次成功续租的时刻（P13）⇒

| 谁 | 受影响时长 |
| --- | --- |
| 同实例的下一次 `acquire` | **0**（`WHERE` 的第二个 `OR` 项 `owner_id = EXCLUDED.owner_id`） |
| 别的实例 | ≤ **1 个 TTL = 90s**（第三个 `OR` 项之前抢不走） |
| `thread_is_held` | ≤ 90s 内仍答 `True` |

而**这正是 `kill -9` 的形状** —— `end_lease` 的 docstring 已经把它写成 built property
（「If this call never runs … the lease simply goes silent and expires, which is the property
being built rather than a gap in it.」）⇒ 一次失败的 release 不引入新状态，只是**退化成崩溃路径**。

## 3. 裁定

### 裁定 A：**不分开**，并把理由从「后果轻」换成可重算的「**零决定者**」（**采纳**）

「后果轻」是一条**估的**判断，下一片没法复核它，也没法知道哪天它不成立。改成：

> **答案的粒度由「谁据此做决定」决定。** 有决定者 ⇒ 两种非答案必须分得开（否则决定会做错）；
> 没有决定者 ⇒ 分开只会造出三个**全都会被丢弃**的值，那是「有一列、没有读者」。

家族表（本片的核心产出，三条都是**量过的**）：

| 问题 | 决定者 | 后果 | 值 |
| --- | --- | --- | --- |
| `acquire`：能不能拿 | 接管扫描 `_takeover.py:139`（拒绝 or 照跑） | 双写 | **3 值**（#636） |
| `renew_outcome`：还能不能续 | 心跳 `_heartbeat_until_cancelled`（停 or 继续） | 红线 4 | **3 值**（#638） |
| `release`：有没有标成 released | **无**（`end_lease:729` 丢弃） | 退化成崩溃路径，≤1 TTL | **保持 `bool`**（本片） |

★ 这条不是「`release` 不重要」，是**它的答案无处可去**。而**原因仍然可见**：`release` 的
`except` 分支自己 `logger.warning`（`:548`），所以「问不到」在日志里是一个可识别的名字
—— 值被丢弃，**理由没有被丢弃**。这是本片允许塌成 `bool` 的全部依据。

### 裁定 B：把「零决定者」与塌陷的形状**都钉成判据**（**采纳**）

两个方向都要，否则裁定会单向失效：

- **正向**：新增主张 `readers_of_the_release_answer` = **0**（重算 = 模块外调用点数 + 模块内
  调用点上「值被读」的处数）。**有人给它加了一个决定者 ⇒ 这条红** ⇒ 被迫回来重裁。
- **反向**：新增主张 `release_collapses_the_two_non_answers` = **true**（重算 = `except` 分支
  返回的那个值，与「不是我们的」那一档返回的值相同）。**有人分了它 ⇒ 这条红** ⇒ 被迫把
  文档与裁定一起改（同 #639 的「两档都停」那条判据的形状）。

`0` 与 `true` 都是**自带不了对照**的值（#635/#639 的教训）⇒ 两条都必须配**同批进来的**正对照，
夹具要在一个合成树上让它们答出**另一个值**。

### 裁定 C：`except` 那一档**不补读侧见证，补一条日志见证**；并把它登记成「声明的缺口」（**采纳**）

P9 说那一档零见证。但要问的是**补什么样的见证**：

- **返回值不需要见证** —— 它的效果（`False`）与另外两档**同值**，一条「assert 它是 False」的
  用例只是在测那个塌陷本身（而塌陷正是裁定 A 认可的东西）。
- **需要见证的是它说了什么**：`logger.warning("execution_leases release failed for %s: %s")`
  是这个成员**唯一**可观察的产物（同 #638 那条「断言要写在那个产物上」）。

⇒ 补一条用例：让 pool 在 release 时抛，断言 `except` 被走到、日志里有那一行、且返回值是
`False`。它同时证明「问不到」在**本仓最容易复现的形态**（内存后端**拼不出**它）下仍然可识别。

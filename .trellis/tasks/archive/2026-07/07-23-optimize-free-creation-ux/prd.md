## 背景

自由创作入口默认进入 Agent 对话模式，用户应当可以直接描述创作目标，并在需要时使用草稿命令管理内容。当前实现有三处明显的交互断点：

1. `/start` 已出现在自由模式的首屏提示、Tab 补全和命令模式分发中，但默认 Agent 分发器没有对应 case，用户会得到“未知命令”。
2. Agent WebSocket 尚未连接或已断开时，普通文本调用不会得到任何反馈，`isProcessing` 还可能保持为 true，首条创作目标会被静默丢弃。
3. 自动重连耗尽后只有静态终端提示，没有可见的重试入口；移动端输入框在未连接时还会退化成“输入命令”的误导性提示。

## 产品目标

- 自由模式的首屏命令、Tab 补全和 Agent/命令两种分发路径保持一致。
- 连接状态可理解：用户能区分已连接、连接中和已断开，并知道下一步动作。
- 连接建立期间输入的第一条创作目标不丢失，重连成功后自动发送；达到重试上限后仍保留待发送消息。
- 移动端与桌面端获得相同的状态反馈和恢复路径。
- 非自由模式只保留现有行为；不引入后端接口或线程状态。

## 需求

### UX-01：统一自由模式命令入口

- 在 `processAgentCommand` 中支持自由模式 `/start`，语义为发送 `new_session` 并显示“已开启新会话”。
- 自由模式的工作流命令在 Agent 模式也给出隔离提示，不落入静默未知命令；非自由模式逻辑不变。
- 保持 `/drafts`、`/draft`、`/edit`、`/delete`、`/evaluate`、`/analytics`、`/suggest` 两种分发器已有能力。

### UX-02：连接状态与恢复动作

- 状态栏在自由模式展示本地化的“已连接 / 连接中 / 未连接”状态。
- 自动重连期间状态保持为连接中；达到上限后状态为未连接，并显示可点击的“重试连接”快捷操作。
- 手动重试清理旧定时器、重置重试计数，不能创建并行 WebSocket 连接。
- 快捷操作提供“新会话”，降低用户记忆 `/start` 的成本；所有触控目标保持至少 44px。

### UX-03：连接期间输入不丢失

- 自由模式下 Agent 未连接时提交的普通文本进入有上限的待发送队列，并显示明确的暂存提示。
- WebSocket 建立后按输入顺序发送待发送消息；连接彻底失败时队列保留，用户点击重试即可继续。
- 发送控制类 `/start` 在未连接时不伪装成功，给出连接提示并保持可恢复状态。
- 移动端输入框在自由模式下始终使用“输入创作目标/消息”语义；不可发送空白内容。

## 验收标准

- `/tui?mode=free` 默认 Agent 模式下输入 `/start` 不再显示未知命令，并发送 `new_session`。
- Agent 未连接时输入普通文本有可见反馈，组件不永久停留在处理中；重连后文本只发送一次且顺序不变。
- 自动重连耗尽后能看到未连接状态和“重试连接”按钮；点击不会产生并行 socket。
- 自由模式移动端 placeholder、连接提示、重试动作均有中英文文案。
- `npm run i18n:check`、`npm run type-check`、相关 Vitest 测试通过。
- `.trellis/spec/backend/free-creation.md` 记录 Agent 分发器、连接恢复和待发送消息的交互契约。

## 技术约束

- 使用现有 `AgentTUI.vue`、`client`、xterm.js 和 WebSocket，不新增状态管理 store。
- 新增字符串必须同时写入 `frontend/src/locales/zh-CN.json` 与 `frontend/src/locales/en.json`。
- 连接队列只存在于当前 TUI 会话，不写入 localStorage 或后端，避免跨账号/跨会话污染。

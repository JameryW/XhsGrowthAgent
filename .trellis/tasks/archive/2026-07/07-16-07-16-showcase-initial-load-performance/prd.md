# 首页首屏数据加载优化

## 背景

公开首页（Showcase）在已登录浏览器中仍会等待一次 token 校验，之后才开始渲染工作流列表。列表返回后，首屏卡片还要逐个请求详情；网络延迟较高时，用户会长时间看到骨架屏或卡片空状态。

## 目标

- 公开首页和回放页首屏不再被非必要的登录态校验阻塞。
- 首页优先复用本次会话内的新鲜列表/详情数据，让二次进入即时可见，同时后台刷新保证数据新鲜。
- 保持现有错误、筛选、重试和详情并发控制行为，不引入跨用户或持久化敏感数据。

## 方案

1. 路由守卫对公开沉浸页（首页、回放）跳过首屏 token validate；访问受保护路由或登录页时仍按原逻辑校验。
2. Showcase 将列表结果及已成功的详情结果写入 `sessionStorage`，使用短 TTL（30 秒）和版本化 key。命中缓存时立即展示并继续请求后台刷新；缓存不可用、过期或解析失败时按现有请求流程执行。
3. 缓存命中后只对缺失详情发请求；刷新列表时清理已不存在的详情，避免内存和请求队列残留。

## 验收标准

- 已有会话缓存时，首页在网络请求返回前即可显示列表内容；首次访问仍显示现有骨架屏。
- 公开首页/回放路由不再等待 `validateToken`；受保护页面的鉴权行为不变。
- 缓存 TTL 到期后自动后台刷新，刷新失败仍保留可用的旧列表并允许用户重试。
- `npm run build`、相关 lint/typecheck 通过；不改变详情请求的并发上限和用户可见错误提示。

## 非目标

- 不修改后端接口协议、数据库查询或工作流状态语义。
- 不将工作流数据写入 localStorage、URL 或服务端缓存。

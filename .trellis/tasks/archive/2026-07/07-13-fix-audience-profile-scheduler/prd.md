# 修复观众画像导入与定时同步

## 现状与问题

生产账号已经能导入创作者中心的账户指标、观看来源和观看时段，但观众画像为空。当前 CDP 客户端通过 `?noteId=...` 打开笔记详情，而响应捕获逻辑只读取 `note_id` 查询参数，因此详情接口的画像响应没有按笔记归档，最终不会落库。

服务的定时同步器目前启动后先等待整个间隔才执行首轮同步；同步器只写日志，没有持久/健康状态，HTTP 200 也不能直接判断批次是否成功。这使得服务重启后的数据会长时间保持旧快照，也无法从健康检查确认任务是否执行。

## 目标

1. CDP 笔记详情捕获同时支持 Creator Center 使用的 `noteId`、`note_id` 参数，并覆盖详情响应的画像/来源/趋势数据，确保归一化后能落库并由观众分析接口返回。
2. 对捕获到的详情响应做可验证的单元测试，避免参数命名或响应包络变化再次静默丢失画像。
3. 定时同步器启动后立即执行首轮同步，随后按配置间隔执行；保留取消和单账号隔离语义。
4. 在 `/health` 中公开调度器的启用、运行中、上次结果/错误和下一次计划时间，且日志记录开始与完成批次摘要。健康状态不得暴露 cookie、签名或原始画像内容。
5. 保持手动同步 API 的结果语义不变，并让测试能明确区分 HTTP 响应成功与导入批次成功。

## 完成标准

- 新增/更新测试证明 `noteId` 详情请求可被归档，画像能进入 `NoteStats`/`audience_analysis`。
- 新增/更新测试证明调度器首轮立即运行、完成/异常时更新状态、取消时退出。
- 相关后端测试、ruff 和类型检查通过。
- 运行服务健康接口能显示调度器状态；下一次实际同步后数据库 `synced_at`、画像覆盖率和调度日志相互一致。

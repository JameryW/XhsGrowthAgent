# 完整前端体验升级

## 背景

上一轮 PR 已修复路由、错误恢复、移动端入口、快捷键和账号上下文等交互问题，但页面整体视觉层级仍接近旧版。用户在 Dashboard 和开始创作页上无法明显感知“优化已完成”，因此需要补一轮面向首屏任务完成率的可见升级。

## 目标

- 让开始创作页在 5 秒内说明“现在可以做什么、需要什么、下一步是什么”。
- 让 Dashboard 首屏聚焦当前工作流状态和唯一主行动，而不是先展示长时间线。
- 让空状态、进行中、等待用户输入和已完成状态都有不同的视觉层级与明确 CTA。
- 在移动端保持同一套信息优先级，并确保主要动作触控区域至少 44px。
- 使用已有 i18n、Pinia 和组件规范，不改变后端接口和工作流状态语义。

## 范围

1. 重构 `Home.vue` 的首屏欢迎区、模式选择说明、当前账号摘要和快捷入口。
2. 重构 `Dashboard.vue` 的状态英雄区、进度摘要、下一步行动卡和空状态。
3. 提升 `WorkflowStartForm.vue` 的模式卡片、步骤提示和表单分组可读性。
4. 为上述新交互补齐中英文文案与组件级测试，并更新前端交互文档/README。
5. 重新构建、部署并对真实健康端点和静态前端入口验收。

## 非目标

- 不修改后端 API、工作流节点或数据库结构。
- 不替换现有视觉主题；升级重点是层级、空间、状态和行动路径。

## 验收标准

- `/start` 首屏存在清晰的标题/说明、账号摘要、模式卡片和主行动；窄屏无横向溢出。
- `/dashboard` 在无工作流、运行中、等待输入、等待审核、已完成状态下分别显示对应的主行动或状态摘要。
- 主行动按钮可通过键盘访问，触控高度不小于 44px，所有新增文案同时存在于 `en.json` 与 `zh-CN.json`。
- `npm run type-check`、`npm run test:run`、`npm run build` 通过；新增测试覆盖关键状态分支。
- 部署后 `GET /` 返回 200，`/api/system/health` 与 Ripple `/healthz` 均通过。

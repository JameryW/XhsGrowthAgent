# 两条修复路径差的是四个性质，不是一行

> 后续票。`09-18-execution-plane-cost-model`（PR #631）把 §7 那条「一行」的**代价**钉住了；
> 这张票钉住它的**形状** —— 因为「一行」这个说法本身量错了。

## 0. 结论：**「补一行」把差异算小了**

§7 的「留给下一任务的输入」第 1 条写的是「给 `_run_retry` 补注册表写入 —— 一行，与 `:363` 同形」。
PR #631 已经证明**代价**不是一行；本片量的是**形状**：两条修复路径的实际差异是 **5 个性质**，
而其中 3 个不是「补一个键」能解决的。

| 性质 | `retry_ripple_analysis`（定义 `_wf_actions.py:38`） | `retry_publish`（定义 `:193`） |
|---|---|---|
| 串行化守卫 `process_has_active_task` | **0** | 1（`:228`） |
| `asyncio.create_task` | 1（`:181`） | 1（`:361`） |
| `add_done_callback` | **0** | 1（`:362`） |
| `_background_tasks[...] =` | **0** | 1（`:363`） |
| 被起协程的**自身清理**（`finally` + `pop`） | **0** | 1（`_run_publish_retry`：`:320` 的 `try` / `:357-359` 的 `finally`） |
| 租约（`start_lease`） | 0 | **0** |

★ 最后一行是 §7 的原始事实（两条都不持租约），本片不动；**前五行里 4 行是缺口**。

## 1. 为什么它不是「四个独立的一行」

三个耦合，全部有出处：

1. **注册表 ⇒ 别人的判断。** 补上它会让 `process_has_active_task` 在窗口内答 True，而那个谓词有
   2 个「读到 True 就不干活」的消费者（`_wf_actions.py:228`、`_wf_application.py:1675`），并经
   `_runner.py:91` 波及 7 个状态侧消费者 —— 已由 #631 钉住，窗口 **1800 秒**。
2. **守卫：缺的不是一个键，是整条守卫。** `retry_ripple_analysis` 里 `process_has_active_task`
   出现 **0** 次 —— 它**没有**兄弟路径那条「工作流正在跑就不允许再触发」。而 `:222` 的注释写着
   「工作流正在跑（**含正在重试**）时不允许再触发」⇒ **让兄弟路径看见「正在重试」原本就是意图**；
   今天反而是 ripple 路径能在工作流跑着的时候直接写 checkpoint（这正是 P2b 登记的那件事）。
3. **done 回调：没有守卫就不能照抄。** `_on_task_done` 在任务正常结束而库里仍是 `running` 时把状态
   写成 **`stale`**（`backend/api/routes/_wf_runtime.py:97-99`）。publish-retry 能安全用它，正因为
   它有守卫（跑它的时候没别的东西在跑）。ripple 路径没有守卫 ⇒ 照抄回调会把**真的在跑**的工作流
   标成 stale。

⇒ 「补一行」的真实形状是：**4 个性质 + 2 个必须先答的问题**（守卫答什么、回调要不要）。
本片只把这个形状变成可重算的判据，**不做那笔改动**。

## 5. 验收

1. §7 的每个性质都有一个重算器；每个重算器都在 §7 被发布（三向闭环）。
2. 有一条**成对**断言：两条路径的同一性质**不相等**（否则「差异」这个词本身就是错的）。
3. `*_done_callbacks` / `*_self_cleanups` 各有一个**能看见正面**的夹具。
4. 全文行号解析规则仍绿（本片会新增引用，规则会跟着核对）。
5. 四道门禁全绿，且 `passed + skipped` 的增量恰好等于新增用例数。

## 6. 待决裁定

- **守卫答什么？** 让 ripple 路径也拒绝「工作流正在跑」，会改掉一个今天可用的行为（用户在工作流跑着
  的时候点重试，今天会跑、之后会 `skipped`）。`:222` 的注释支持后者，但那是**兄弟路径**的注释。
- **回调要不要？** 要就必须先有守卫，否则 `stale` 会写错。⇒ 两个问题有顺序，不能分开答。

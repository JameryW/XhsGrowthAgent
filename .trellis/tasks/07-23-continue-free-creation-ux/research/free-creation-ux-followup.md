# 自由创作交互后续审查

## 当前证据

- `AgentTUI.vue` 在自由入口默认使用 Agent 模式，WebSocket 断开时切换到 command mode，并将自然语言消息放入最多 5 条的内存队列。
- `sendFreeNewSession()` 在 socket 不可用时只显示不可用提示，不保留“新会话”意图。
- `onclose` 只在自动重连耗尽时重置 `isProcessing`；如果中途重连成功，生成中的终端提示可能仍处于处理中。
- 快捷操作目前执行 `/start`、`/suggest`、`/drafts` 等命令，没有可编辑的自然语言示例。

## 设计决策

### 1. 新会话意图与消息队列分离

新增组件生命周期内的 `pendingFreeNewSession` 标记。触发新会话时先丢弃当前自然语言队列，再设置标记；重连时先发送 `new_session`，随后只发送该操作之后新进入的消息。该标记不写入 localStorage，也不跨账号或组件实例。

### 2. 断线即结束当前本地 turn

WebSocket 断开意味着当前终端无法继续接收流式结果，因此立即清除 `isProcessing` 并输出一次中断提示。重连只恢复连接和队列发送，不假设服务端会补发已经丢失的流。

### 3. 示例只预填，不自动调用 Agent

自由创作可能触发模型调用、草稿写入或发布流程。示例按钮采用“预填输入”的低风险交互：桌面端更新终端输入行，移动端更新原生输入框，用户确认后才发送。

## 风险与验证

- 需要覆盖新会话优先级，避免旧消息穿透到新上下文。
- 需要覆盖断线重连后 `isProcessing` 可恢复。
- 需要覆盖桌面和移动端预填逻辑，避免点击示例直接发送。
- 继续运行 i18n parity、vue-tsc、Vitest 全量和 Vite build。

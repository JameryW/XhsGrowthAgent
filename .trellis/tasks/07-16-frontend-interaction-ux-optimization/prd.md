## 1. 摘要

本轮不是继续叠加视觉效果，而是把当前前端从“每个模块都能展示”提升为“用户沿一条清晰路径完成判断”。核心路径为：

> 找到真实案例 → 快速判断案例价值 → 进入回放 → 定位阶段与检查点 → 读取真实产出 → 返回原上下文或开始创作

展示页负责建立信任并把用户送入有价值的案例；回放页负责解释 AI 工作流具体做了什么、产出了什么。其余页面以全局导航、状态反馈、动作层级和跨页连续性为主，不在首轮做大规模换肤。

本 PRD 统一收束仓库中多轮 `07-15-*` 展示页、回放页和全站体验任务。已有实现作为当前基线，不再以多个并行视觉任务重复迭代；后续实施应按本 PRD 的优先级与统一验收标准拆分。

## 3. 产品目标

### 3.1 用户目标

1. 新访客在 5 秒内理解产品用途，并在首屏或紧邻首屏的位置看到真实案例证据。
2. 用户在展示页最多两次操作即可打开目标工作流回放。
3. 用户进入回放后无需理解内部状态模型，即可回答：
   - 这个工作流当前/最终处于什么状态？
   - 我现在查看的是哪个阶段、哪个检查点？
   - 该步骤做了什么、产出了什么？
   - 最终内容与核心指标是什么？
4. 用户返回展示页时保留筛选、排序和浏览位置。
5. 移动端用户不需要先滚过大型装饰内容，便能查看真实工作流与回放结果。

### 3.2 产品目标

- 提升展示页到回放页的案例打开率。
- 降低进入回放后、看到首个真实结果前的退出率。
- 提升回放检查点的实际浏览率和回放后的创作 CTA 转化。
- 将临时加载失败从“内容缺失”转化为可恢复状态。
- 建立可复用的全站交互规则，减少后续页面各自演化。

### 3.3 非目标

- 不修改后端工作流节点、状态语义、数据库结构或内容生成逻辑。
- 不新增公开数据字段，不扩大现有公开接口的数据暴露范围。
- 不替换现有品牌配色和 Liquid Glass 视觉主题。
- 不把展示页改成纯营销官网，也不把回放页改成可编辑 Dashboard。
- 不在本轮重写所有认证页面；P1/P2 仅治理共性体验和关键断点。

## 4. 用户与场景

| 用户 | 核心任务 | 当前阻力 | 目标结果 |
| --- | --- | --- | --- |
| 首次访问者 | 了解产品是否真的能完成小红书内容工作流 | 装饰先于证据，案例入口不够直接 | 先看到价值主张与真实案例，快速进入一个代表性回放 |
| 潜在客户/合作方 | 检查 AI 每一步的过程、产出和最终效果 | 实时进度、历史进度与最终摘要语义混合 | 能按阶段和检查点审阅，最终结果保持稳定 |
| 已登录运营者 | 从工作台或历史记录查看过程，再返回继续操作 | 回放固定返回公开展示页 | 返回来源页面并保留 thread 上下文 |
| 移动端浏览者 | 快速扫一遍案例和关键结果 | 大型流程视觉把真实内容推到首屏之后 | 一屏内看到真实状态入口或所选结果标题 |
| 键盘/低动态偏好用户 | 完成同样的浏览与选择 | 卡片语义、焦点、连续动画仍需统一 | 所有入口可键盘操作，状态不只靠颜色或动效表达 |

## 5. 体验原则

1. **真实证据优先**：实际工作流和结果优先于装饰性流程说明。
2. **一个区域一个主动作**：同一屏内避免两个视觉权重相同、目的相近的 CTA。
3. **实时状态与历史选择分离**：实时状态回答“现在在哪里”，历史选择回答“我正在看哪里”。
4. **渐进披露**：首屏只展示判断所需信息，详细过程按需展开。
5. **状态必须可解释、可恢复**：加载、部分数据、空、失败和无权限不能共用含糊空白。
6. **跨页上下文连续**：筛选、滚动、来源和所选检查点应可恢复或深链。
7. **移动端不是压缩桌面版**：移动端调整阅读顺序，装饰默认弱化或后置。

## 6. 目标用户旅程

```text
展示页进入
  → 看懂一句价值主张 + 真实工作流概览
  → 筛选/排序/搜索案例
  → 打开工作流
  → 回放页显示工作流身份 + 当前/最终状态
  → 默认定位最近一个有意义的检查点
  → 浏览阶段 / 检查点 / 真实结果
  → 查看稳定的最终输出摘要
  → 返回原列表位置，或登录后开始创作
```

## 7. P0：展示页优化需求

### SHOW-01 页面信息架构重排

展示页调整为以下阅读顺序：

1. 轻量顶部导航：品牌、登录/进入工作台入口。
2. 紧凑 Hero：一句价值主张、一句解释、一个主 CTA、一个次级文本入口。
3. 真实工作流工作区：状态概览、推荐/最新案例、筛选与工作流列表。
4. “如何工作”流程说明：保留闭环识别，但降为辅助解释。
5. 可信信息与页脚。

要求：

- 桌面 `1440 × 900` 首屏必须出现真实工作流工作区的入口及至少一条真实工作流的可识别信息。
- 移动端 `390 × 844` 首屏必须出现实时案例入口；闭环流程默认使用紧凑 2 × 3 网格或折叠摘要，不得横向裁切节点。
- 现有闭环动画可保留为品牌识别，但面积、持续动效和视觉对比度均低于真实案例区域。
- Hero 与顶部导航不得出现两个等权的“开始创作/进入工作台”按钮。

### SHOW-02 真实工作流工作区

- 将推荐案例纳入同一工作流列表：推荐项可跨列或置顶，但不得在下方列表重复出现。
- 推荐项必须标注“推荐案例/最近活跃/需要关注”等可理解原因，不暴露内部评分算法。
- 状态概览只使用用户可理解的集合：全部、活跃、已完成、需关注；卡片仍展示精确状态。
- 当数据量较少时不制造空洞的大型统计区；统计信息采用紧凑行或与筛选区合并。
- 列表默认按最近更新排序，加载更多后保持当前筛选和顺序稳定。
- P1 可增加标题/品牌/主题关键词搜索；数据量不足 8 条时搜索框可不展示。

### SHOW-03 筛选与浏览上下文

- 状态、模式和排序同步到 URL query，建议键为 `status`、`mode`、`sort`。
- 返回展示页时恢复筛选、排序、已加载数量和滚动锚点。
- 筛选切换后，将焦点或可视区域移动到结果摘要，而不是跳到页面顶部。
- 无筛选结果时展示当前筛选条件、结果数 0、重置筛选操作。
- 非法 query 自动回退默认值，不产生空白页面。

### SHOW-04 工作流卡片

卡片信息层级固定为：

1. 工作流标题/主题。
2. 精确状态 + 阶段 + 进度。
3. 一项最能证明价值的真实产出摘要，例如文案标题、品牌/产品、发布结果或核心指标。
4. 更新时间、模式等元信息。
5. 唯一动作“查看回放”。

交互要求：

- 卡片使用真实链接语义，可聚焦、回车打开，并支持浏览器原生新标签页行为。
- 整卡可点击时，不得吞掉卡内链接、复制或文本选择操作。
- 仅用颜色不足以表达状态，必须同时有状态文案或图标。
- 详情后到达时保持卡片最小高度，避免布局跳动。
- 卡片详情失败时保留列表级标题、状态和进度，并提供单卡重试；不得永久进入不可重试状态。
- `error`、`stale`、`paused`、`cancelled` 等状态使用不同的解释文案，不统一映射成泛化“异常”。

### SHOW-05 CTA 与认证分流

- 未登录用户主 CTA 为“开始创作”，进入 `/login?redirect=/start`。
- 已登录用户主 CTA 为“进入工作台”或“开始新创作”，直接进入对应认证路由。
- 从回放页触发创作 CTA 时携带来源事件，但不自动复制案例内容或创建工作流。
- CTA 触发后立即提供按压/导航反馈，禁止重复提交。

### SHOW-06 展示页状态模型

| 状态 | 页面表现 | 必须操作 |
| --- | --- | --- |
| 首次加载 | Hero 立即可见；工作流区显示与最终结构同高的 skeleton | `aria-busy`，不阻塞页面其他操作 |
| 列表成功 | 展示统计、筛选、推荐项和列表 | 正常浏览 |
| 列表失败 | 展示错误原因的用户化摘要 | 重试列表；Hero/CTA 保持可用 |
| 真空态 | 明确说明暂无公开工作流 | 开始创作；不展示无意义筛选器 |
| 筛选空态 | 展示当前条件无结果 | 一键重置筛选 |
| 详情加载 | 卡片主体局部 skeleton，外框和标题稳定 | 可直接进入回放，不强制等待详情 |
| 详情部分成功 | 展示已有字段，对缺失字段不占空卡 | 仍可进入回放 |
| 详情失败 | 降级展示列表级信息 | 单卡重试、查看回放 |

### SHOW-07 性能与动效

- 保留“先列表、后详情”策略；首批立即详情请求不超过推荐项加 3 张可见卡片，并发不超过 3。
- 非首屏详情只在浏览器空闲、接近视口或用户展开时请求。
- 切换筛选时不重复请求已有详情，不因推荐项变化形成请求风暴。
- 背景粒子、轨道和扫光不得延迟真实内容显示；低性能/移动端减少持续动画层。
- reduced-motion 下内容立即可见，所有有延迟且带 backwards/both fill-mode 的入场动画必须显式关闭。

## 8. P0：工作流回放页优化需求

### REPLAY-01 明确两套时间语义

回放页必须明确区分：

- **工作流状态**：来自当前 `workflowState`，描述流程最终或实时状态、真实进度和最后更新时间。
- **查看位置**：来自 `selectedCheckpoint`，描述用户正在查看第几步、哪个代理、何时生成。

要求：

- 不再用 `effectiveState` 同时驱动工作流实时进度和历史检查点进度。
- 顶部只显示一条工作流状态；选择历史检查点后显示“正在查看：第 N 步 · 代理 · 时间”。
- 历史阶段条表达“所选检查点所在阶段”，不得显示成另一条与实时百分比竞争的进度。
- 已完成、失败、暂停和等待人工操作均使用真实工作流状态，不因所选历史检查点改变。

### REPLAY-02 结果优先的页面结构

桌面阅读顺序：

1. 工作流身份、返回路径、工作流状态。
2. 紧凑阶段导航。
3. 检查点导航 + 选中检查点结果 + 稳定最终摘要。
4. 辅助流程视觉或技术说明。

桌面建议布局：

```text
┌ 返回 / 工作流标题 / 当前或最终状态 / 主动作 ┐
├ 阶段导航：已完成 · 当前 · 待处理 ──────────┤
├ 检查点 220px ┬ 选中步骤真实结果 1fr ┬ 最终摘要 280px ┤
└ 辅助说明或折叠的流程可视化 ───────────────┘
```

要求：

- `1440 × 900` 首屏必须看到选中检查点的结果标题及首块真实内容。
- 当前大型“创作过程”轨道图降级为可折叠辅助区，或移动到核心结果之后。
- 三列布局只在空间充足时启用；中等宽度可采用检查点抽屉 + 结果 + 摘要两列。
- 右侧摘要不得挤压中心结果到不可读宽度。

### REPLAY-03 默认选择与阶段导航

默认检查点选择顺序：

1. URL 指定且有效的 `checkpoint`。
2. 最近一个包含可展示业务结果的检查点。
3. 最近一个检查点。
4. 无检查点时进入明确空态。

阶段导航要求：

- 阶段按钮同时表达已完成、所选、失败/中断和未到达，状态不只依赖颜色。
- 点击阶段后选中该阶段最近一个包含有效数据的检查点；若没有可查看检查点，按钮禁用并说明原因。
- 检查点按阶段分组，项目显示步骤号、用户化代理名称、时间和数据可用性。
- 选中检查点后更新 URL query，刷新或复制链接可恢复同一位置。
- 加载更多检查点后保持当前选择和滚动位置。

### REPLAY-04 移动端回放

- `390 × 844` 首屏必须看到工作流状态、检查点入口和选中结果标题。
- 阶段导航保持横向滑动，但首次选中项自动滚入可视区并提供边缘渐隐提示。
- 检查点 chips 改为“当前检查点摘要 + 打开全部检查点”控件；完整列表使用底部抽屉或全宽可折叠面板。
- 结果内容位于装饰性画布之前；最终摘要在结果之后，或以折叠摘要呈现。
- 固定/粘性控件不得遮挡结果内容和系统安全区。
- 在 `320`、`390`、`768` 像素宽度下不得出现页面级横向滚动。

### REPLAY-05 结果与最终摘要

- 中间区域只展示当前选中检查点的结果，标题始终包含代理名称、步骤号和时间。
- “本步骤无业务数据”与“数据加载失败”使用不同状态；技术错误可折叠查看，默认展示可理解说明。
- 最终摘要由当前工作流状态或最新有效最终检查点计算，不随历史检查点选择变化。
- 最终摘要至少支持：最终标题/主题、品牌/产品、发布状态/链接、核心 Ripple 指标、分析指标；只展示真实存在字段。
- 若流程尚未产生最终结果，摘要明确显示“尚未生成”，不得用当前步骤数据冒充最终结果。
- 发布失败、鉴权失败等状态提供原因分类；公开回放只给说明，不提供会改变工作流的操作。

### REPLAY-06 返回、深链与分享

- 从展示页进入时携带来源与列表上下文；返回后恢复筛选和滚动。
- 从认证工作区进入时返回对应 thread 的 Dashboard、History 或 Review，而不是固定返回 `/`。
- 直接访问深链时，返回按钮安全回退到展示页。
- 支持复制当前检查点链接；埋点和分享 URL 不包含内容正文、账号敏感信息或认证凭证。
- 无效 threadId 或 checkpoint 必须展示可恢复页面，并提供返回案例列表入口。

### REPLAY-07 回放页状态模型

| 状态 | 页面表现 | 必须操作 |
| --- | --- | --- |
| 页面初始化 | 工作流身份 skeleton + 工作区结构 skeleton | 不先显示“无数据” |
| 状态与检查点均成功 | 默认选中有效检查点并展示结果 | 正常浏览 |
| 状态成功、检查点加载中 | 保留工作流状态，检查点区局部加载 | 可等待或重试 |
| 状态失败、检查点成功 | 以部分数据模式继续回放 | 说明实时/最终状态暂不可用，支持重试 |
| 状态成功、无检查点 | 显示真实无检查点原因 | 返回案例、刷新 |
| 检查点失败 | 不将失败显示为“暂无检查点” | 重试检查点请求 |
| thread 不存在 | 专用 404/已删除状态 | 返回展示页 |
| 检查点无业务数据 | 保留步骤上下文 | 选择相邻有效检查点 |
| 检查点参数失效 | 提示已回退到最近有效检查点 | 更新 URL，不打断浏览 |

### REPLAY-08 回放状态实现边界

- `workflowStore` 保留 live state 和 replay selection 两个明确来源；派生显示状态使用 computed，不在模板临时拼装。
- 回放入口和退出必须清理当前页面的临时选择，但不得破坏认证工作区保存的 active thread。
- 工作流状态请求和检查点请求分别记录 loading/error，禁止单个布尔值合并所有状态。
- 代理到阶段的映射保持 trend/brief 两种模式一致，并为 fallback 选择补充单元测试。
- 不为视觉优化增加额外轮询；公开回放默认使用现有状态与检查点 API。

## 9. P1：全站交互一致性

### 9.1 全局规则

- 页面标题区固定表达：页面目的、当前上下文、唯一主动作、必要的次级动作。
- 全站按钮分为主动作、次动作、危险动作和文本动作；同一区域最多一个主动作。
- 统一列表级加载、局部加载、空、筛选空、错误、部分数据和无权限组件语义。
- 路由切换后焦点进入主内容标题；返回列表时恢复触发入口或结果区焦点。
- 所有导航项、卡片入口、筛选器和菜单支持键盘；触控目标不小于 44px。
- Toast 用于已发生的短反馈，页面内状态用于需要持续查看或恢复的问题；同一错误不得同时重复弹 Toast 和错误卡。
- 所有新增可见文案同时写入 `zh-CN.json` 和 `en.json`。

### 10.2 上线后目标

先采集 7 天基线，再以同口径比较：

## 11. 性能与质量预算

- 公开展示页 p75 LCP 目标不高于 2.5 秒，CLS 不高于 0.1，核心交互响应目标不高于 200ms。
- 展示页首个真实列表在常规移动网络下 2.5 秒内出现；详情失败不得阻塞列表。
- 回放页首个可用检查点结果在接口成功后 300ms 内渲染。
- 首屏不得因为详情 hydration、字体或背景动画出现明显布局跳动。
- 不增加同步大依赖；Showcase 和 Replay 继续按路由拆包，代理结果组件可按需要评估异步加载。
- 所有持续动画只修改 `transform`/`opacity` 等合成友好属性；移动端和 reduced-motion 使用静态降级。

## 12. 无障碍与国际化

- 所有可点击卡片使用链接或按钮语义，并有可见 focus ring。
- 阶段、检查点和筛选控件使用正确的 `aria-current`、`aria-pressed`、`aria-expanded` 或列表语义。
- 加载完成、错误恢复和检查点切换使用克制的 live region；不得反复朗读全部结果。
- 状态除颜色外同时提供文本/图标；正文与交互控件满足 AA 级对比度目标。
- reduced-motion 下取消入场延迟、轨道持续运动、脉冲和自动滚动动画，但保留内容与状态。
- 日期、数字与百分比使用当前 locale 格式，禁止固定 `zh-CN`。
- 中英文长度差异下不裁切主标题、状态和主动作。

## 17. 产品决策记录

### 决策 1：真实案例先于流程装饰

展示页的核心说服力来自真实工作流，不来自更复杂的背景和轨道动画。因此真实案例前置，流程闭环保留但降级为辅助解释。

### 决策 2：回放是审阅工具，不是动画演示页

用户进入回放的主要任务是定位步骤并读取结果。阶段动效只帮助理解位置，不能把结果推到首屏之后。

### 决策 3：最终摘要必须稳定

历史检查点选择只改变“正在查看的步骤”，不改变“工作流最终产出”。两者必须使用不同数据来源和视觉容器。

### 决策 4：先完成 P0 闭环，再铺开全站

展示页和回放页共同组成公开转化与信任链路，应先独立验收。全站一致性以共享规则逐页落地，避免再次形成多轮无统一指标的视觉微调。
